# 1장: 간단한 웹 서버 (A Simple Web Server)

> **검수 메모:** 원본 PDF 7~23페이지의 마지막 요약까지 번역 내용이 수록되어 있습니다. PDF 7~12페이지의 본문 및 예제에 대한 1차 세부 대조를 진행했으며, PDF 13~23페이지와 전체 코드 문자 단위 대조는 아직 완료되지 않았습니다.

이 장에서는 Java 웹 서버가 어떻게 동작하는지 설명한다. 웹 서버는 일반적으로 웹 브라우저인 클라이언트와 통신할 때 HTTP(Hypertext Transfer Protocol)를 사용하므로 HTTP 서버라고도 부른다. Java 기반 웹 서버는 `java.net.Socket`과 `java.net.ServerSocket`이라는 두 가지 중요한 클래스를 사용하며, 통신은 HTTP 메시지를 통해 이루어진다. 따라서 먼저 HTTP와 이 두 클래스를 살펴보는 것이 자연스럽다. 이후 이 장에 포함된 간단한 웹 서버 애플리케이션을 설명한다.

## HTTP(Hypertext Transfer Protocol)

HTTP는 웹 서버와 브라우저가 인터넷을 통해 데이터를 주고받도록 하는 프로토콜이다. 요청과 응답으로 이루어지는 프로토콜로, 클라이언트가 파일을 요청하면 서버가 그 요청에 응답한다. HTTP는 신뢰할 수 있는 TCP 연결을 사용하며 기본 포트는 TCP 80번이다. 최초의 HTTP 버전은 HTTP/0.9였고, 이후 HTTP/1.0으로 대체되었다. 이 책에서 현재 버전으로 다루는 HTTP/1.1은 HTTP/1.0을 대체했으며 RFC 2616에 정의되어 있다. 원문에서 안내하는 문서 주소는 `http://www.w3.org/Protocols/HTTP/1.1/rfc2616.pdf`이다.

> **참고:** 이 절은 웹 서버 애플리케이션이 전송하는 메시지를 이해하는 데 필요한 HTTP/1.1의 개요만 간략히 다룬다. 자세한 내용은 RFC 2616을 참고하라.

HTTP에서는 항상 클라이언트가 연결을 설정하고 HTTP 요청을 전송하여 통신을 시작한다. 웹 서버가 먼저 클라이언트에 접속하거나 클라이언트로 콜백 연결을 만들 수는 없다. 클라이언트와 서버 모두 연결을 조기에 종료할 수 있다. 예를 들어 웹 브라우저에서 중지 버튼을 클릭하면 파일 다운로드가 중단되고 웹 서버와의 HTTP 연결이 종료된다.

### HTTP 요청

HTTP 요청은 다음 세 부분으로 구성된다.

- 메서드(Method) — URI(Uniform Resource Identifier) — 프로토콜/버전
- 요청 헤더(Request headers)
- 엔티티 본문(Entity body)

다음은 HTTP 요청의 예다.

```http
POST /examples/default.jsp HTTP/1.1
Accept: text/plain; text/html
Accept-Language: en-gb
Connection: Keep-Alive
Host: localhost
User-Agent: Mozilla/4.0 (compatible; MSIE 4.01; Windows 98)
Content-Length: 33
Content-Type: application/x-www-form-urlencoded
Accept-Encoding: gzip, deflate

lastName=Franks&firstName=Michael
```

요청의 첫 번째 줄에는 메서드, URI, 프로토콜 버전이 나타난다.

```http
POST /examples/default.jsp HTTP/1.1
```

여기서 `POST`는 요청 메서드, `/examples/default.jsp`는 URI, `HTTP/1.1`은 프로토콜/버전을 나타낸다.

HTTP 요청에는 HTTP 표준에서 정한 여러 요청 메서드 중 하나를 사용할 수 있다. HTTP/1.1은 `GET`, `POST`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`, `TRACE`라는 일곱 가지 요청 유형을 지원한다. 인터넷 애플리케이션에서는 `GET`과 `POST`가 가장 널리 사용된다.

URI는 인터넷 리소스를 완전하게 식별한다. URI는 보통 서버의 루트 디렉터리를 기준으로 한 상대 경로로 해석되므로 슬래시(`/`)로 시작해야 한다. URL(Uniform Resource Locator)은 URI의 한 종류다(원문 참고 링크: `http://www.ietf.org/rfc/rfc2396.txt`). 프로토콜 버전은 사용 중인 HTTP 프로토콜의 버전을 나타낸다.

요청 헤더에는 클라이언트 환경과 요청의 엔티티 본문에 관한 유용한 정보가 들어 있다. 예를 들어 브라우저에 설정된 언어, 엔티티 본문의 길이 등이 포함될 수 있다. 각 헤더는 CRLF(Carriage Return/Line Feed) 시퀀스로 구분된다.

헤더와 엔티티 본문 사이에는 빈 줄(CRLF)이 하나 있으며, 이는 HTTP 요청 형식에서 중요하다. 이 CRLF를 통해 HTTP 서버는 엔티티 본문이 어디서 시작되는지 알 수 있다. 일부 인터넷 프로그래밍 서적에서는 이 CRLF를 HTTP 요청의 네 번째 구성 요소로 간주한다.

앞의 HTTP 요청에서 엔티티 본문은 다음 한 줄이다.

```text
lastName=Franks&firstName=Michael
```

일반적인 HTTP 요청에서는 엔티티 본문이 훨씬 길어질 수 있다.

### HTTP 응답

HTTP 요청과 마찬가지로 HTTP 응답도 다음 세 부분으로 구성된다.

- 프로토콜 — 상태 코드 — 설명
- 응답 헤더(Response headers)
- 엔티티 본문(Entity body)

다음은 HTTP 응답의 예다.

```http
HTTP/1.1 200 OK
Server: Microsoft-IIS/4.0
Date: Mon, 5 Jan 2004 13:13:33 GMT
Content-Type: text/html
Last-Modified: Mon, 5 Jan 2004 13:13:12 GMT
Content-Length: 112

<html>
<head>
<title>HTTP Response Example</title>
</head>
<body>
Welcome to Brainy Software
</body>
</html>
```

응답의 첫 번째 줄은 요청의 첫 번째 줄과 비슷하다. 이 줄은 사용된 프로토콜이 HTTP/1.1이고 요청이 성공했으며(`200`은 성공을 의미한다), 모든 처리가 정상적으로 이루어졌음을 알려준다.

응답 헤더에도 요청 헤더와 마찬가지로 유용한 정보가 들어 있다. 응답의 엔티티 본문은 응답 자체의 HTML 콘텐츠다. 헤더와 엔티티 본문은 CRLF 시퀀스로 구분된다.

## Socket 클래스

소켓은 네트워크 연결의 끝점(endpoint)이다. 소켓을 사용하면 애플리케이션이 네트워크에서 데이터를 읽고 쓸 수 있다. 서로 다른 컴퓨터에서 실행되는 두 소프트웨어 애플리케이션은 연결을 통해 바이트 스트림을 송수신하며 통신할 수 있다. 자신의 애플리케이션에서 다른 애플리케이션으로 메시지를 보내려면 상대 애플리케이션 소켓의 IP 주소와 포트 번호를 알아야 한다. Java에서 소켓은 `java.net.Socket` 클래스로 표현된다.

소켓을 만들 때는 `Socket` 클래스가 제공하는 여러 생성자 중 하나를 사용할 수 있다. 그중 하나는 호스트 이름과 포트 번호를 인수로 받는다.

```java
public Socket (java.lang.String host, int port)
```

여기서 `host`는 원격 컴퓨터의 이름 또는 IP 주소이며, `port`는 원격 애플리케이션의 포트 번호다. 예를 들어 `yahoo.com`의 80번 포트에 연결하려면 다음과 같이 `Socket` 객체를 생성한다.

```java
new Socket ("yahoo.com", 80);
```

`Socket` 인스턴스를 성공적으로 생성하면 바이트 스트림을 송수신할 수 있다. 바이트 스트림을 보내려면 먼저 `Socket` 클래스의 `getOutputStream` 메서드를 호출하여 `java.io.OutputStream` 객체를 얻어야 한다. 원격 애플리케이션으로 텍스트를 보낼 때는 반환된 `OutputStream` 객체로 `java.io.PrintWriter` 객체를 생성하는 경우가 많다. 연결의 반대쪽에서 바이트 스트림을 받으려면 `Socket` 클래스의 `getInputStream` 메서드를 호출한다. 이 메서드는 `java.io.InputStream`을 반환한다.

다음 코드는 로컬 HTTP 서버와 통신할 수 있는 소켓을 생성하고(`127.0.0.1`은 로컬 호스트를 뜻한다), HTTP 요청을 보낸 뒤 서버로부터 응답을 받는다. 응답을 저장할 `StringBuffer` 객체를 만들고 콘솔에 출력한다.

```java
Socket socket = new Socket("127.0.0.1", "8080");
OutputStream os = socket.getOutputStream();
boolean autoflush = true;
PrintWriter out = new PrintWriter(
  socket.getOutputStream(), autoflush);
BufferedReader in = new BufferedReader(
  new InputStreamReader( socket.getInputstream() ));

// send an HTTP request to the web server
out.println("GET /index.jsp HTTP/1.1");
out.println("Host: localhost:8080");
out.println("Connection: Close");
out.println();

// read the response
boolean loop = true;
StringBuffer sb = new StringBuffer(8096);
while (loop) {
  if (in.ready()) {
    int i = 0;
    while (i != -1) {
      i = in.read();
      sb.append((char) i);
    }
    loop = false;
  }
  Thread.currentThread().sleep(50);
}

// display the response to the out console
System.out.println(sb.toString());
socket.close();
```

웹 서버로부터 올바른 응답을 받으려면 HTTP 프로토콜을 준수하는 요청을 보내야 한다. 앞의 HTTP 절을 읽었다면 위 코드의 HTTP 요청을 이해할 수 있을 것이다.

> **참고:** 이 책에 포함된 `com.brainysoftware.pyrmont.util.HttpSniffer` 클래스를 사용하면 HTTP 요청을 보내고 응답을 표시할 수 있다. 이 Java 프로그램을 사용하려면 인터넷에 연결되어 있어야 한다. 다만 방화벽 뒤에 있다면 동작하지 않을 수 있다.



## ServerSocket 클래스 (The ServerSocket Class)

`Socket` 클래스는 원격 서버 애플리케이션에 연결할 때 생성하는 **클라이언트 소켓**을 나타낸다. 반면 HTTP 서버나 FTP 서버처럼 서버 애플리케이션을 구현하려면 다른 접근 방식이 필요하다. 클라이언트가 언제 연결을 시도할지 알 수 없으므로 서버는 항상 연결을 기다리고 있어야 하기 때문이다. 이처럼 연결 요청을 계속 기다리게 하려면 서버 소켓을 구현한 `java.net.ServerSocket` 클래스를 사용한다.

`ServerSocket`은 `Socket`과 다르다. 서버 소켓의 역할은 클라이언트의 연결 요청을 기다리는 것이다. 연결 요청을 받으면 클라이언트와 통신할 `Socket` 인스턴스를 생성한다.

서버 소켓을 만들 때는 `ServerSocket`이 제공하는 네 가지 생성자 중 하나를 사용한다. 서버 소켓이 수신 대기할 IP 주소와 포트 번호를 지정해야 한다. 일반적으로 IP 주소는 로컬 컴퓨터를 의미하는 `127.0.0.1`이다. 서버 소켓이 수신 대기하는 IP 주소를 **바인딩 주소(binding address)**라고 한다. 서버 소켓의 또 다른 중요한 속성은 **백로그(backlog)**다. 백로그는 서버 소켓이 새 연결 요청을 거부하기 전에 대기열에 보관할 수 있는 연결 요청의 최대 개수를 의미한다.

생성자 중 하나의 선언은 다음과 같다.

```java
public ServerSocket(int port, int backLog, InetAddress bindingAddress);
```

이 생성자에서 바인딩 주소는 `java.net.InetAddress`의 인스턴스여야 한다. `InetAddress` 객체를 만드는 간단한 방법은 호스트 이름을 문자열로 전달해 정적 메서드 `getByName`을 호출하는 것이다.

```java
InetAddress.getByName("127.0.0.1");
```

다음 코드는 로컬 컴퓨터의 8080 포트에서 수신 대기하고 백로그가 1인 `ServerSocket`을 생성한다.

```java
new ServerSocket(8080, 1, InetAddress.getByName("127.0.0.1"));
```

`ServerSocket` 인스턴스를 만들었다면 해당 바인딩 주소와 포트로 들어오는 연결 요청을 기다리도록 할 수 있다. 이를 위해 `ServerSocket`의 `accept` 메서드를 호출한다. 이 메서드는 연결 요청이 들어와야 반환되며, 반환값은 `Socket` 인스턴스다. 앞의 「Socket 클래스」 절에서 설명한 것처럼 이 객체로 클라이언트 애플리케이션과 바이트 스트림을 주고받을 수 있다. 실제로 이 장의 예제 애플리케이션에서 사용하는 서버 소켓 메서드는 `accept`뿐이다.

## 애플리케이션 (The Application)

웹 서버 예제는 `ex01.pyrmont` 패키지에 속하며 세 클래스로 구성된다.

- `HttpServer`
- `Request`
- `Response`

애플리케이션의 진입점인 정적 `main` 메서드는 `HttpServer` 클래스에 있다. `main`은 `HttpServer` 인스턴스를 만들고 `await` 메서드를 호출한다. 이름 그대로 `await`는 지정한 포트에서 HTTP 요청을 기다렸다가 요청을 처리하고 클라이언트에 응답을 보낸다. 종료 명령을 받을 때까지 이 동작을 계속한다.

이 애플리케이션은 특정 디렉터리에 있는 HTML 파일이나 이미지 파일 등의 **정적 리소스**만 전송할 수 있다. 또한 수신한 HTTP 요청의 바이트 스트림을 콘솔에 표시한다. 하지만 날짜나 쿠키 같은 헤더는 브라우저에 보내지 않는다.

이제 다음 절에서 세 클래스를 살펴보자.

### HttpServer 클래스

`HttpServer` 클래스는 웹 서버를 나타내며 목록 1.1에 제시되어 있다. 공간을 절약하기 위해 `await` 메서드는 목록 1.1에 반복해서 싣지 않고 목록 1.2에 별도로 제시한다.

**목록 1.1: HttpServer 클래스**

```java
package ex01.pyrmont;

import java.net.Socket;
import java.net.ServerSocket;
import java.net.InetAddress;
import java.io.InputStream;
import java.io.OutputStream;
import java.io.IOException;
import java.io.File;

public class HttpServer {
  /** WEB_ROOT is the directory where our HTML and other files reside.
   * For this package, WEB_ROOT is the "webroot" directory under the
   * working directory.
   * The working directory is the location in the file system
   * from where the java command was invoked.
   */
  public static final String WEB_ROOT =
    System.getProperty("user.dir") + File.separator + "webroot";

  // shutdown command
  private static final String SHUTDOWN_COMMAND = "/SHUTDOWN";

  // the shutdown command received
  private boolean shutdown = false;

  public static void main(String[] args) {
    HttpServer server = new HttpServer();
    server.await();
  }

  public void await() {
    ...
  }
}
```

**목록 1.2: HttpServer 클래스의 await 메서드**

```java
public void await() {
  ServerSocket serverSocket = null;
  int port = 8080;
  try {
    serverSocket = new ServerSocket(port, 1,
      InetAddress.getByName("127.0.0.1"));
  }
  catch (IOException e) {
    e.printStackTrace();
    System.exit(1);
  }
  // Loop waiting for a request
  while (!shutdown) {
    Socket socket = null;
    InputStream input = null;
    OutputStream output = null;
    try {
      socket = serverSocket.accept();
      input = socket.getInputStream();
      output = socket.getOutputStream();
      // create Request object and parse
      Request request = new Request(input);
      request.parse();

      // create Response object
      Response response = new Response(output);
      response.setRequest(request);
      response.sendStaticResource();

      // Close the socket
      socket.close();
      //check if the previous URI is a shutdown command
      shutdown = request.getUri().equals(SHUTDOWN_COMMAND);
    }
    catch (Exception e) {
      e.printStackTrace();
      continue;
    }
  }
}
```

이 웹 서버는 `public static final` 상수 `WEB_ROOT`가 가리키는 디렉터리와 그 하위 디렉터리의 정적 리소스를 제공한다. `WEB_ROOT`는 다음과 같이 초기화한다.

```java
public static final String WEB_ROOT =
  System.getProperty("user.dir") + File.separator + "webroot";
```

예제 코드에는 테스트용 정적 리소스를 담은 `webroot` 디렉터리가 포함되어 있다. 이후 장의 애플리케이션을 테스트할 때 사용할 서블릿도 이 디렉터리에 여러 개 들어 있다.

정적 리소스를 요청하려면 브라우저 주소 입력란에 다음 형식의 URL을 입력한다.

```text
http://machineName:port/staticResource
```

애플리케이션을 실행하는 컴퓨터와 다른 컴퓨터에서 요청한다면 `machineName`은 서버 컴퓨터의 이름 또는 IP 주소다. 같은 컴퓨터의 브라우저를 사용한다면 `localhost`를 지정할 수 있다. `port`는 `8080`이고, `staticResource`는 `WEB_ROOT`에 있는 요청 파일의 이름이다.

예를 들어 같은 컴퓨터에서 `HttpServer`가 `index.html`을 보내도록 요청하려면 다음 주소를 사용한다.

```text
http://localhost:8080/index.html
```

서버를 중지하려면 브라우저 주소 입력란에서 URL의 `host:port` 부분 뒤에 미리 정의한 종료 문자열을 입력해 종료 명령을 보낸다. 종료 명령은 `HttpServer` 클래스의 `SHUTDOWN_COMMAND` 정적 상수로 정의한다.

```java
private static final String SHUTDOWN_COMMAND = "/SHUTDOWN";
```

따라서 서버를 중지할 때 사용하는 URL은 다음과 같다.

```text
http://localhost:8080/SHUTDOWN
```

이제 목록 1.2의 `await` 메서드를 살펴보자. `wait` 대신 `await`라는 이름을 사용하는 이유는 `wait`가 스레드 작업에 사용되는 `java.lang.Object` 클래스의 중요한 메서드이기 때문이다.

`await`는 먼저 `ServerSocket` 인스턴스를 만들고 `while` 반복문으로 진입한다.

```java
serverSocket = new ServerSocket(port, 1,
  InetAddress.getByName("127.0.0.1"));
...
// Loop waiting for a request
while (!shutdown) {
  ...
}
```

반복문 안의 코드는 `ServerSocket`의 `accept` 메서드에서 대기한다. 이 메서드는 8080 포트로 HTTP 요청이 들어왔을 때만 반환한다.

```java
socket = serverSocket.accept();
```

요청을 받으면 `await`는 `accept`가 반환한 `Socket` 인스턴스에서 `java.io.InputStream`과 `java.io.OutputStream` 객체를 얻는다.

```java
input = socket.getInputStream();
output = socket.getOutputStream();
```

그다음 `ex01.pyrmont.Request` 객체를 생성하고 `parse` 메서드를 호출하여 HTTP 요청의 원시 데이터를 파싱한다.

```java
// create Request object and parse
Request request = new Request(input);
request.parse();
```

이어서 `Response` 객체를 생성하고 여기에 `Request` 객체를 설정한 뒤 `sendStaticResource` 메서드를 호출한다.

```java
// create Response object
Response response = new Response(output);
response.setRequest(request);
response.sendStaticResource();
```

마지막으로 `Socket`을 닫고 `Request`의 `getUri` 메서드를 호출해 요청 URI가 종료 명령인지 확인한다. 종료 명령이면 `shutdown` 변수를 `true`로 설정하고 `while` 반복문을 빠져나온다.

```java
// Close the socket
socket.close();
//check if the previous URI is a shutdown command
shutdown = request.getUri().equals(SHUTDOWN_COMMAND);
```

### Request 클래스

`ex01.pyrmont.Request` 클래스는 HTTP 요청을 나타낸다. 클라이언트와 통신하는 `Socket`에서 얻은 `InputStream` 객체를 전달하여 이 클래스의 인스턴스를 생성한다. HTTP 요청의 원시 데이터는 `InputStream` 객체의 `read` 메서드 중 하나를 호출해 얻는다.

`Request` 클래스는 목록 1.3에 제시되어 있다. 이 클래스에는 두 개의 공개 메서드 `parse`와 `getUri`가 있으며, 각각 목록 1.4와 1.5에 제시한다.

**목록 1.3: Request 클래스**

```java
package ex01.pyrmont;

import java.io.InputStream;
import java.io.IOException;

public class Request {
  private InputStream input;
  private String uri;

  public Request(InputStream input) {
    this.input = input;
  }

  public void parse() {
    ...
  }

  private String parseUri(String requestString) {
    ...
  }

  public String getUri() {
    return uri;
  }
}
```

**목록 1.4: Request 클래스의 parse 메서드**

```java
public void parse() {
  // Read a set of characters from the socket
  StringBuffer request = new StringBuffer(2048);
  int i;
  byte[] buffer = new byte[2048];
  try {
    i = input.read(buffer);
  }
  catch (IOException e) {
    e.printStackTrace();
    i = -1;
  }
  for (int j=0; j<i; j++) {
    request.append((char) buffer[j]);
  }
  System.out.print(request.toString());
  uri = parseUri(request.toString());
}
```

**목록 1.5: Request 클래스의 parseUri 메서드**

```java
private String parseUri(String requestString) {
  int index1, index2;
  index1 = requestString.indexOf(' ');
  if (index1 != -1) {
    index2 = requestString.indexOf(' ', index1 + 1);
    if (index2 > index1)
      return requestString.substring(index1 + 1, index2);
  }
  return null;
}
```

`parse` 메서드는 HTTP 요청의 원시 데이터를 파싱한다. 이 메서드가 하는 일은 많지 않다. `parseUri`라는 비공개 메서드를 호출해 얻은 HTTP 요청의 URI만 사용할 수 있도록 한다. `parseUri`는 URI를 `uri` 변수에 저장한다. 공개 메서드 `getUri`는 HTTP 요청의 URI를 반환한다.

> **참고:** HTTP 요청의 원시 데이터를 더 자세히 처리하는 방법은 3장과 이후 장의 예제에서 다룬다.

`parse`와 `parseUri`의 동작을 이해하려면 앞의 「HTTP」 절에서 다룬 HTTP 요청의 구조를 알아야 한다. 이 장에서는 HTTP 요청의 첫 부분인 **요청 라인(request line)**에만 관심을 둔다. 요청 라인은 메서드 토큰으로 시작하고, 요청 URI와 프로토콜 버전이 뒤따르며, 캐리지 리턴과 줄 바꿈 문자(CRLF)로 끝난다. 각 요소는 공백 문자로 구분한다. 예를 들어 GET 메서드로 `index.html` 파일을 요청하는 요청 라인은 다음과 같다.

```http
GET /index.html HTTP/1.1
```

`parse`는 `Request` 객체에 전달된 소켓의 `InputStream`에서 바이트 스트림을 읽어 바이트 배열 버퍼에 저장한다. 그런 다음 버퍼의 바이트를 사용해 `request`라는 `StringBuffer` 객체를 채우고, 이를 문자열로 변환하여 `parseUri`에 전달한다. `parse` 메서드는 목록 1.4에 제시되어 있다.

`parseUri`는 요청 라인에서 URI를 추출한다. 목록 1.5에 제시된 이 메서드는 요청 문자열에서 첫 번째와 두 번째 공백을 찾아 그 사이에 있는 URI를 가져온다.

### Response 클래스

`ex01.pyrmont.Response` 클래스는 HTTP 응답을 나타내며 목록 1.6에 제시되어 있다.

**목록 1.6: Response 클래스**

```java
package ex01.pyrmont;

import java.io.OutputStream;
import java.io.IOException;
import java.io.FileInputStream;
import java.io.File;

/*
  HTTP Response = Status-Line
    *(( general-header | response-header | entity-header ) CRLF)
    CRLF
    [ message-body ]
  Status-Line = HTTP-Version SP Status-Code SP Reason-Phrase CRLF
*/

public class Response {
  private static final int BUFFER_SIZE = 1024;
  Request request;
  OutputStream output;

  public Response(OutputStream output) {
    this.output = output;
  }

  public void setRequest(Request request) {
    this.request = request;
  }

  public void sendStaticResource() throws IOException {
    byte[] bytes = new byte[BUFFER_SIZE];
    FileInputStream fis = null;
    try {
      File file = new File(HttpServer.WEB_ROOT, request.getUri());
      if (file.exists()) {
        fis = new FileInputStream(file);
        int ch = fis.read(bytes, 0, BUFFER_SIZE);
        while (ch!=-1) {
          output.write(bytes, 0, ch);
          ch = fis.read(bytes, 0, BUFFER_SIZE);
        }
      }
      else {
        // file not found
        String errorMessage = "HTTP/1.1 404 File Not Found\r\n" +
          "Content-Type: text/html\r\n" +
          "Content-Length: 23\r\n" +
          "\r\n" +
          "<h1>File Not Found</h1>";
        output.write(errorMessage.getBytes());
      }
    }
    catch (Exception e) {
      // thrown if cannot instantiate a File object
      System.out.println(e.toString());
    }
    finally {
      if (fis!=null)
        fis.close();
    }
  }
}
```

먼저 생성자가 다음과 같이 `java.io.OutputStream` 객체를 받는다는 점에 주목하자.

```java
public Response(OutputStream output) {
  this.output = output;
}
```

`Response` 객체는 `HttpServer`의 `await` 메서드에서 소켓으로부터 얻은 `OutputStream` 객체를 전달해 생성한다.

`Response` 클래스에는 `setRequest`와 `sendStaticResource`라는 두 개의 공개 메서드가 있다. `setRequest`는 `Request` 객체를 `Response` 객체에 전달하는 데 사용한다.

`sendStaticResource`는 HTML 파일과 같은 정적 리소스를 전송한다. 먼저 부모 경로와 자식 경로를 `File` 생성자에 전달해 `java.io.File` 객체를 생성한다.

```java
File file = new File(HttpServer.WEB_ROOT, request.getUri());
```

그런 다음 파일이 존재하는지 확인한다. 존재한다면 `File` 객체를 전달해 `java.io.FileInputStream` 객체를 생성한다. 이어서 `FileInputStream`의 `read` 메서드를 호출하고 읽은 바이트 배열을 `OutputStream`인 `output`에 기록한다. 이때 정적 리소스의 내용은 가공되지 않은 원시 데이터 형태로 브라우저에 전송된다.

```java
if (file.exists()) {
  fis = new FileInputStream(file);
  int ch = fis.read(bytes, 0, BUFFER_SIZE);
  while (ch!=-1) {
    output.write(bytes, 0, ch);
    ch = fis.read(bytes, 0, BUFFER_SIZE);
  }
}
```

파일이 존재하지 않으면 `sendStaticResource` 메서드는 브라우저에 오류 메시지를 보낸다.

```java
String errorMessage = "HTTP/1.1 404 File Not Found\r\n" +
  "Content-Type: text/html\r\n" +
  "Content-Length: 23\r\n" +
  "\r\n" +
  "<h1>File Not Found</h1>";
output.write(errorMessage.getBytes());
```
