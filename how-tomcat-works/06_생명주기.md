# 6장: 생명주기(Lifecycle)

## 개요 (원본 PDF 130쪽)

Catalina는 많은 컴포넌트로 구성된다. Catalina를 시작하면 이 컴포넌트들도 시작해야 한다. Catalina를 중지할 때에도 각 컴포넌트가 정리 작업을 수행할 기회를 주어야 한다. 예를 들어 컨테이너가 중지되면 로드된 모든 서블릿의 `destroy()` 메서드를 호출해야 하고, 세션 관리자는 세션 객체를 보조 저장소에 저장해야 한다. 컴포넌트를 일관된 방식으로 시작하고 중지하는 메커니즘은 `org.apache.catalina.Lifecycle` 인터페이스를 구현함으로써 제공된다.

`Lifecycle` 인터페이스를 구현하는 컴포넌트는 `BEFORE_START_EVENT`, `START_EVENT`, `AFTER_START_EVENT`, `BEFORE_STOP_EVENT`, `STOP_EVENT`, `AFTER_STOP_EVENT` 가운데 하나 이상의 이벤트를 발생시킬 수도 있다. 일반적으로 처음 세 이벤트는 컴포넌트가 시작할 때, 나머지 세 이벤트는 중지할 때 발생한다. 이벤트는 `org.apache.catalina.LifecycleEvent` 클래스로 표현한다. Catalina 컴포넌트가 이벤트를 발생시킬 수 있다면, 당연히 그 이벤트에 반응하는 이벤트 리스너도 작성할 수 있어야 한다. 리스너는 `org.apache.catalina.LifecycleListener` 인터페이스로 표현한다.

이 장에서는 `Lifecycle`, `LifecycleEvent`, `LifecycleListener` 세 가지 유형을 설명한다. 또한 컴포넌트가 생명주기 이벤트를 발생시키고 생명주기 리스너를 관리하기 쉽게 해 주는 유틸리티 클래스 `LifecycleSupport`도 설명한다. 이 장에서는 `Lifecycle` 인터페이스를 구현하는 클래스들로 프로젝트를 만든다. 애플리케이션은 5장의 애플리케이션을 바탕으로 한다.

## `Lifecycle` 인터페이스 (원본 PDF 130쪽)

Catalina는 한 컴포넌트가 다른 컴포넌트를 포함할 수 있도록 설계되었다. 예를 들어 컨테이너는 Loader, Manager 등의 컴포넌트를 포함할 수 있다. 부모 컴포넌트는 자식 컴포넌트를 시작하고 중지할 책임이 있다. Catalina는 하나를 제외한 모든 컴포넌트를 부모 컴포넌트의 관리 아래 두도록 설계되었기 때문에, 부트스트랩 클래스는 단 하나의 컴포넌트만 시작하면 된다. 이처럼 하나의 시작·중지 메커니즘을 사용할 수 있는 것은 `Lifecycle` 인터페이스 덕분이다. 목록 6.1의 `Lifecycle` 인터페이스를 살펴보자.

**목록 6.1: `Lifecycle` 인터페이스** — 코드는 다음 PDF 페이지(131쪽)에 이어진다.

```java
package org.apache.catalina;
```



## `Lifecycle` 인터페이스 (계속, 원본 PDF 131쪽)

**목록 6.1: `Lifecycle` 인터페이스의 나머지 코드**

```java
public interface Lifecycle {
  public static final String START_EVENT = "start";
  public static final String BEFORE_START_EVENT = "before_start";
  public static final String AFTER_START_EVENT = "after_start";
  public static final String STOP_EVENT = "stop";
  public static final String BEFORE_STOP_EVENT = "before_stop";
  public static final String AFTER_STOP_EVENT = "after_stop";

    public void addLifecycleListener(LifecycleListener listener);
    public LifecycleListener[] findLifecycleListeners();
    public void removeLifecycleListener(LifecycleListener listener);
    public void start() throws LifecycleException;
    public void stop() throws LifecycleException;
}
```

`Lifecycle`에서 가장 중요한 메서드는 `start`와 `stop`이다. 컴포넌트는 이 메서드들을 구현하여 부모 컴포넌트가 자신을 시작하거나 중지할 수 있게 한다.

나머지 세 메서드인 `addLifecycleListener`, `findLifecycleListeners`, `removeLifecycleListener`는 리스너와 관련이 있다. 컴포넌트에는 자신에게서 발생하는 특정 이벤트에 관심을 가진 리스너가 있을 수 있다. 이벤트가 발생하면 그 이벤트에 관심이 있는 리스너에 통지한다. `Lifecycle` 인스턴스가 발생시킬 수 있는 여섯 이벤트의 이름은 인터페이스의 `public static final String` 상수로 정의되어 있다.

## `LifecycleSupport` 클래스 (원본 PDF 132~134쪽)

`Lifecycle`을 구현하고 리스너가 자신의 이벤트에 관심을 등록하도록 허용하는 컴포넌트는 `Lifecycle` 인터페이스의 리스너 관련 메서드 세 개(`addLifecycleListener`, `findLifecycleListeners`, `removeLifecycleListener`)를 구현해야 한다. 또한 등록된 리스너를 배열이나 `ArrayList` 또는 유사한 객체에 저장해야 한다.

Catalina는 컴포넌트가 리스너를 관리하고 생명주기 이벤트를 발생시키는 작업을 쉽게 수행할 수 있도록 유틸리티 클래스 `org.apache.catalina.util.LifecycleSupport`를 제공한다. 목록 6.4는 `LifecycleSupport` 클래스를 보여 준다.

**목록 6.4: `LifecycleSupport` 클래스**

```java
package org.apache.catalina.util;
import org.apache.catalina.Lifecycle;
import org.apache.catalina.LifecycleEvent;
import org.apache.catalina.LifecycleListener;

public final class LifecycleSupport {
  public LifecycleSupport(Lifecycle lifecycle) {
     super();
     this.lifecycle = lifecycle;
  }

  private Lifecycle lifecycle = null;
  private LifecycleListener listeners[] = new LifecycleListener[0];
  public void addLifecycleListener(LifecycleListener listener) {
     synchronized (listeners) {
       LifecycleListener results[] =
          new LifecycleListener[listeners.length + 1];
       for (int i = 0; i < listeners.length; i++)
          results[i] = listeners[i];
       results[listeners.length] = listener;
          listeners = results;
     }
  }

  public LifecycleListener[] findLifecycleListeners() {
    return listeners;
  }

  public void fireLifecycleEvent(String type, Object data) {
    LifecycleEvent event = new LifecycleEvent(lifecycle, type, data);
    LifecycleListener interested[] = null;
    synchronized (listeners) {
       interested = (LifecycleListener[]) listeners.clone();
    }
    for (int i = 0; i < interested.length; i++)
            interested[i].lifecycleEvent(event);
    }

    public void removeLifecycleListener(LifecycleListener listener) {
      synchronized (listeners) {
         int n = -1;
         for (int i = 0; i < listeners.length; i++) {
             if (listeners[i] == listener) {
                 n = i;
                 break;
             }
         }
         if (n < 0)
             return;
         LifecycleListener results[] =
             new LifecycleListener[listeners.length - 1];

            int j = 0;
            for (int i = 0; i < listeners.length; i++) {
               if (i != n)
               results[j++] = listeners[i];
            }
            listeners = results;
        }
    }
}
```

목록 6.4에서 볼 수 있듯이 `LifecycleSupport`는 모든 생명주기 리스너를 `listeners`라는 배열에 저장한다. 이 배열은 처음에는 원소가 없다.

```java
private LifecycleListener listeners[] = new LifecycleListener[0];
```

`addLifecycleListener` 메서드로 리스너를 추가할 때는 기존 배열보다 원소를 하나 더 담을 수 있는 새 배열을 만든다. 그런 다음 기존 배열의 모든 원소를 새 배열에 복사하고 새 리스너를 추가한다. `removeLifecycleListener` 메서드로 리스너를 제거할 때에도 기존 배열보다 원소가 하나 적은 새 배열을 만든다. 그리고 제거할 원소를 제외한 모든 원소를 새 배열로 복사한다.

`fireLifecycleEvent` 메서드는 생명주기 이벤트를 발생시킨다. 먼저 `listeners` 배열을 복제한다. 그런 다음 복제된 배열의 각 원소에 대해 `lifecycleEvent` 메서드를 호출하면서 발생한 이벤트를 인자로 전달한다.

## `LifecycleSupport` 사용 예 (원본 PDF 135쪽)

`Lifecycle`을 구현하는 컴포넌트는 `LifecycleSupport` 클래스를 사용할 수 있다. 예를 들어 이 장의 예제 애플리케이션에 포함된 `SimpleContext` 클래스는 다음 변수를 선언한다.

```java
protected LifecycleSupport lifecycle = new LifecycleSupport(this);
```

생명주기 리스너를 추가하려면 `SimpleContext` 클래스에서 `LifecycleSupport`의 `addLifecycleListener` 메서드를 호출한다.

```java
public void addLifecycleListener(LifecycleListener listener) {
  lifecycle.addLifecycleListener(listener);
}
```

생명주기 리스너를 제거하려면 `LifecycleSupport`의 `removeLifecycleListener` 메서드를 호출한다.

```java
public void removeLifecycleListener(LifecycleListener listener) {
  lifecycle.removeLifecycleListener(listener);
}
```

이벤트를 발생시키려면 다음 코드처럼 `LifecycleSupport`의 `fireLifecycleEvent` 메서드를 호출한다.

```java
lifecycle.fireLifecycleEvent(START_EVENT, null);
```

## 애플리케이션 (원본 PDF 135쪽)

이 장의 예제 애플리케이션은 5장의 애플리케이션을 확장하여 `Lifecycle` 인터페이스와 생명주기 관련 타입의 사용법을 보여 준다. 이 애플리케이션에는 하나의 컨텍스트와 두 개의 래퍼, 로더, 매퍼가 포함되어 있다. 애플리케이션의 컴포넌트들은 `Lifecycle` 인터페이스를 구현하며, 컨텍스트에는 리스너를 사용한다.

애플리케이션을 단순하게 만들기 위해 5장에서 사용한 두 개의 밸브는 여기서는 사용하지 않는다. 애플리케이션의 클래스 다이어그램은 그림 6.1에 나와 있다. 다만 여러 인터페이스(`Container`, `Wrapper`, `Context`, `Loader`, `Mapper`)와 클래스(`SimpleContextValve`, `SimpleContextMapper`, `SimpleWrapperValve`)는 이 그림에서 생략되었다.

## 그림 6.1과 예제 클래스 (원본 PDF 136쪽)

> **그림 6.1**: 예제 애플리케이션의 클래스 다이어그램. 그림 자체는 원본 PDF를 참조한다.

`SimpleContextLifecycleListener` 클래스는 `SimpleContext` 클래스의 리스너를 나타낸다. `SimpleContextValve`, `SimpleContextMapper`, `SimpleWrapperValve` 클래스는 5장에서 사용한 것과 같으므로 여기서는 다시 설명하지 않는다.

### `ex06.pyrmont.core.SimpleContext`

이 애플리케이션의 `SimpleContext` 클래스는 `Lifecycle` 인터페이스를 구현한다는 점을 제외하면 5장의 클래스와 비슷하다. `SimpleContext`는 다음 변수를 통해 `LifecycleSupport` 인스턴스를 참조한다.

```java
protected LifecycleSupport lifecycle = new LifecycleSupport(this);
```

또한 `started`라는 불리언 변수를 사용해 `SimpleContext` 인스턴스가 시작되었는지 나타낸다. `SimpleContext`는 `Lifecycle` 인터페이스에 정의된 메서드를 구현한다. 목록 6.5는 이 메서드들을 보여 준다.

**목록 6.5: `Lifecycle` 인터페이스의 메서드**

```java
public void addLifecycleListener(LifecycleListener listener) {
  lifecycle.addLifecycleListener(listener);
}
public LifecycleListener[] findLifecycleListeners() {
  return null;
}
public void removeLifecycleListener(LifecycleListener listener) {
  lifecycle.removeLifecycleListener(listener);
}
public synchronized void start() throws LifecycleException {
  if (started)
      throw new LifecycleException("SimpleContext has already started");
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(BEFORE_START_EVENT, null);
  started = true;
  try {
      // Start our subordinate components, if any
      if ((loader != null) && (loader instanceof Lifecycle))
          ((Lifecycle) loader).start();

      // Start our child containers, if any
      Container Children[] = findChildren();
      for (int i = 0; i < children.length; i++) {
          if (children[i] instanceof Lifecycle)
              ((Lifecycle) children[i]).start();
      }

      // Start the Valves in our pipeline (including the basic),
      // if any
      if (pipeline instanceof Lifecycle)
          ((Lifecycle) pipeline).start();
      // Notify our Interested LifecycleListeners
      lifecycle.firelifecycleEvent(START_EVENT, null);
  }
  catch (Exception e) {
      e.printStackTrace();
  }
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(AFTER_START_EVENT, null);
}

public void stop() throws LifecycleException {
  if (!started)
      throw new LifecycleException("SimpleContext has not been started");
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(BEFORE_STOP_EVENT, null);
  lifecycle.fireLifecycleEvent(STOP_EVENT, null);
  started = false;
  try {
      // Stop the Valves in our pipeline (including the basic), if any
      if (pipeline instanceof Lifecycle) (

          ((Lifecycle) pipeline).stop();
      }
      // Stop our child containers, if any
      Container children[] = findChildren();
      for (int i = 0; i < children.length; i++) {
          if (children[i] instanceof Lifecycle)
              ((Lifecycle) children[i]).stop();
      }
      if ((loader != null) && (loader instanceof Lifecycle)) {
          ((Lifecycle) loader).stop();
      }
  }
  catch (Exception e) {
      e.printStackTrace();
  }
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(AFTER_STOP_EVENT, null);
}
```

> **원문 코드 주의**: 위 코드는 원본 PDF의 표기를 보존했다. 원문에는 `Children`/`children`, `firelifecycleEvent`/`fireLifecycleEvent`, `if (pipeline instanceof Lifecycle) (`처럼 컴파일 오류로 이어질 수 있는 표기가 포함되어 있다.

`start` 메서드가 모든 자식 컨테이너와 `Loader`, `Pipeline`, `Mapper` 같은 관련 컴포넌트를 시작하고, `stop` 메서드가 이들을 중지하는 방식에 주목하자. 이 메커니즘을 사용하면 컨테이너 모듈의 모든 컴포넌트를 시작하기 위해 계층 구조에서 가장 상위에 있는 컴포넌트(여기서는 `SimpleContext` 인스턴스) 하나만 시작하면 된다. 중지할 때도 동일한 컴포넌트 하나만 중지하면 된다.

`SimpleContext`의 `start` 메서드는 먼저 컴포넌트가 이미 시작되었는지 확인한다. 이미 시작된 경우 `LifecycleException`을 던진다.

```java
if (started)
    throw new LifecycleException(
      "SimpleContext has already started");
```

그런 다음 `BEFORE_START_EVENT` 이벤트를 발생시킨다.

```java
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(BEFORE_START_EVENT, null);
```

그 결과 `SimpleContext` 인스턴스의 이벤트를 수신하도록 등록된 모든 리스너가 알림을 받는다. 이 애플리케이션에는 `SimpleContextLifecycleListener` 타입의 리스너 하나가 등록된다. 이 리스너에서 어떤 일이 일어나는지는 `SimpleContextLifecycleListener` 클래스를 설명할 때 살펴본다.

다음으로 `start` 메서드는 컴포넌트가 시작되었음을 나타내기 위해 `started` 값을 `true`로 설정한다.

```java
started = true;
```

이어서 `start` 메서드는 모든 관련 컴포넌트와 자식 컨테이너를 시작한다. 현재 `Lifecycle` 인터페이스를 구현하는 컴포넌트는 `SimpleLoader`와 `SimplePipeline` 두 개다. `SimpleContext`에는 자식으로 두 개의 래퍼가 있으며, 이들은 `Lifecycle` 인터페이스를 구현하는 `SimpleWrapper` 타입이다.

```java
try {
    // Start our subordinate components, if any
    if ((loader != null) && (loader instanceof Lifecycle))
        ((Lifecycle) loader).start();

    // Start our child containers, if any
    Container children[] = findChildren();
    for (int i = 0; i < children.length; i++) {
        if (children[i] instanceof Lifecycle)
            ((Lifecycle) children[i]).start();
    }

    // Start the Valves in our pipeline (including the basic),
    // if any
    if (pipeline instanceof Lifecycle)
        ((Lifecycle) pipeline).start();
```

컴포넌트와 자식 컨테이너를 시작한 뒤 `start` 메서드는 `START_EVENT`와 `AFTER_START_EVENT`라는 두 이벤트를 발생시킨다.

```java
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(START_EVENT, null);
.
.
.
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(AFTER_START_EVENT, null);
```

`stop` 메서드는 먼저 인스턴스가 시작된 상태인지 확인한다. 시작되지 않았다면 `LifecycleException`을 던진다.

```java
if (!started)
    throw new LifecycleException(
      "SimpleContext has not been started");
```

그런 다음 `BEFORE_STOP_EVENT`와 `STOP_EVENT` 이벤트를 발생시키고 `started` 불리언 값을 초기화한다.

```java
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(BEFORE_STOP_EVENT, null);
lifecycle.fireLifecycleEvent(STOP_EVENT, null);
started = false;
```



## `SimpleContext.stop()`의 나머지 동작 (원본 PDF 140쪽)

다음으로 `stop` 메서드는 자신과 연결된 모든 컴포넌트와 `SimpleContext` 인스턴스의 자식 컨테이너를 중지한다.

```java
try {
    // Stop the Valves in our pipeline (including the basic), if any
    if (pipeline instanceof Lifecycle) {
        ((Lifecycle) pipeline).stop();
    }
    // Stop our child containers, if any
    Container children[] = findChildren();
    for (int i = 0; i < children.length; i++) {
        if (children[i] instanceof Lifecycle)
            ((Lifecycle) children[i]).stop();
    }
    if ((loader != null) && (loader instanceof Lifecycle)) {
        ((Lifecycle) loader).stop();
    }
}
```

마지막으로 `AFTER_STOP_EVENT` 이벤트를 발생시킨다.

```java
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(AFTER_STOP_EVENT, null);
```

## `ex06.pyrmont.core.SimpleContextLifecycleListener` (원본 PDF 140~141쪽)

`SimpleContextLifecycleListener` 클래스는 `SimpleContext` 인스턴스의 리스너를 나타낸다. 목록 6.6에 이 클래스가 제시되어 있다.

**목록 6.6: `SimpleContextLifecycleListener` 클래스**

```java
package ex06.pyrmont.core;
import org.apache.catalina.Context;
import org.apache.catalina.Lifecycle;
import org.apache.catalina.LifecycleEvent;
import org.apache.catalina.LifecycleListener;

public class SimpleContextLifecycleListener implements
LifecycleListener {

  public void lifecycleEvent(LifecycleEvent event) {
    Lifecycle lifecycle = event.getLifecycle();
    System.out.println("SimpleContextLifecycleListener's event " +
        event.getType().toString());
    if (Lifecycle.START_EVENT.equals(event.getType())) {
        System.out.println("Starting context.");
    }
    else if (Lifecycle.STOP_EVENT.equals(event.getType())) {
        System.out.println("Stopping context.");
    }
  }
}
```

`SimpleContextLifecycleListener`의 `lifecycleEvent` 구현은 단순하다. 발생한 이벤트의 유형을 출력할 뿐이다. 이벤트가 `START_EVENT`이면 `Starting context.`를 출력하고, `STOP_EVENT`이면 `Stopping context.`를 출력한다.

## `ex06.pyrmont.core.SimpleLoader` (원본 PDF 141~142쪽)

`SimpleLoader` 클래스는 5장에서 소개한 클래스와 비슷하지만, 이번 애플리케이션에서는 `Lifecycle` 인터페이스를 구현한다는 차이가 있다. 이 클래스의 `Lifecycle` 인터페이스 메서드들은 콘솔에 문자열을 출력하는 것 외에는 별다른 일을 하지 않는다. 하지만 더 중요한 점은 `Lifecycle` 인터페이스를 구현함으로써 연결된 컨테이너가 `SimpleLoader` 인스턴스를 시작할 수 있다는 것이다.

## `ex06.pyrmont.core.SimplePipeline` (원본 PDF 142쪽)

`SimplePipeline` 클래스는 `Pipeline` 인터페이스뿐 아니라 `Lifecycle` 인터페이스도 구현한다. `Lifecycle` 인터페이스의 메서드 구현은 비어 있지만, 이제 연결된 컨테이너가 이 클래스의 인스턴스를 시작할 수 있다. 나머지 부분은 5장의 `SimplePipeline` 클래스와 비슷하다.

## `ex06.pyrmont.core.SimpleWrapper` (원본 PDF 142~144쪽)

이 클래스는 `ex05.pyrmont.core.SimpleWrapper`와 비슷하다. 이번 애플리케이션에서는 부모 컨테이너가 시작할 수 있도록 `Lifecycle` 인터페이스를 구현한다. `start`와 `stop`을 제외한 대부분의 `Lifecycle` 인터페이스 메서드는 비어 있다. 목록 6.8은 해당 인터페이스 메서드의 구현을 보여 준다.

**목록 6.8: `Lifecycle` 인터페이스의 메서드**

```java
public void addLifecycleListener(LifecycleListener listener) { }
public LifecycleListener[] findLifecycleListeners() {
  return null;
}
public void removeLifecycleListener(LifecycleListener listener) ( }
public synchronized void start() throws LifecycleException {
  System.out.println("Starting Wrapper " + name);
  if (started)
      throw new LifecycleException("Wrapper already started");
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(BEFORE_START_EVENT, null);
  started = true;

  // Start our subordinate components, if any
  if ((loader != null) && (loader instanceof Lifecycle))
      ((Lifecycle) loader).start();
  // Start the Valves in our pipeline (including the basic), if any
  if (pipeline instanceof Lifecycle)
      ((Lifecycle) pipeline).start();
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(START_EVENT, null);
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(AFTER_START_EVENT, null);
}

public void stop() throws LifecycleException {
  System.out.println("Stopping wrapper " + name);
  // Shut down our servlet instance (if it has been initialized)
  try {
      instance.destroy();
  }
  catch (Throwable t) {
  }
  instance = null;
  if (!started)
      throw new LifecycleException("Wrapper " + name + " not started");
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(BEFORE_STOP_EVENT, null);
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(STOP_EVENT, null);
  started = false;

  // Stop the Valves in our pipeline (including the basic), if any
  if (pipeline instanceof Lifecycle) {
      ((Lifecycle) pipeline).stop();
  }
  // Stop our subordinate components, if any
  if ((loader != null) && (loader instanceof Lifecycle)) {
      ((Lifecycle) loader).stop();
  }
  // Notify our interested LifecycleListeners
  lifecycle.fireLifecycleEvent(AFTER_STOP_EVENT, null);
}
```

> **원문 코드 주의:** 목록 6.8의 `removeLifecycleListener` 선언에 `( }`가 나타난다. 원문 표기를 그대로 옮겼으며, Java 문법상 정상적인 메서드 본문은 `{ }`여야 한다.

`SimpleWrapper`의 `start` 메서드는 `SimpleContext`의 `start` 메서드와 비슷하다. 추가된 컴포넌트(현재는 없음)를 시작하고 `BEFORE_START_EVENT`, `START_EVENT`, `AFTER_START_EVENT`를 발생시킨다.

`SimpleWrapper`의 `stop` 메서드는 더 흥미롭다. 간단한 문자열을 출력한 뒤 서블릿 인스턴스의 `destroy` 메서드를 호출한다.

```java
System.out.println("Stopping wrapper " + name);
// Shut down our servlet instance (if it has been initialized)
try {
    instance.destroy();
}
catch (Throwable t) {
}
instance = null;
```

그런 다음 래퍼가 시작된 상태인지 검사한다. 시작되지 않았다면 `LifecycleException`을 던진다.

```java
if (!started)
    throw new LifecycleException("Wrapper " + name + " not started");
```

이어서 `BEFORE_STOP_EVENT`와 `STOP_EVENT`를 발생시키고 `started` 불리언 값을 초기화한다.

```java
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(BEFORE_STOP_EVENT, null);
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(STOP_EVENT, null);
started = false;
```

다음으로 연결된 로더와 파이프라인 컴포넌트를 중지한다. 이번 애플리케이션의 `SimpleWrapper` 인스턴스에는 로더가 없다.

```java
// Stop the Valves in our pipeline (including the basic), if any
if (pipeline instanceof Lifecycle) {
    ((Lifecycle) pipeline).stop();
}
// Stop our subordinate components, if any
if ((loader != null) && (loader instanceof Lifecycle)) {
    ((Lifecycle) loader).stop();
}
```

마지막으로 `AFTER_STOP_EVENT`를 발생시킨다.

```java
// Notify our interested LifecycleListeners
lifecycle.fireLifecycleEvent(AFTER_STOP_EVENT, null);
```

## 애플리케이션 실행 (원본 PDF 144~145쪽)

Windows에서 애플리케이션을 실행하려면 작업 디렉터리에서 다음 명령을 입력한다.

```sh
java -classpath ./lib/servlet.jar;./ ex06.pyrmont.startup.Bootstrap
```

Linux에서는 두 라이브러리를 구분할 때 콜론을 사용한다.

```sh
java -classpath ./lib/servlet.jar:./ ex06.pyrmont.startup.Bootstrap
```

콘솔에는 다음 메시지가 표시된다. 여러 이벤트가 발생하는 순서에 주목하자.

```text
HttpConnector Opening server socket on all host IP addresses
HttpConnector[8080] Starting background thread
SimpleContextLifecycleListener's event before_start
Starting SimpleLoader
Starting Wrapper Modern
Starting Wrapper Primitive
SimpleContextLifecycleListener's event start
Starting context.
SimpleContextLifecycleListener's event after_start
```

브라우저에서 `PrimitiveServlet`을 호출하려면 다음 URL을 사용한다.

```text
http://localhost:8080/Primitive
```

`ModernServlet`을 호출하려면 다음 URL을 사용한다.

```text
http://localhost:8080/Modern
```

## 요약 (원본 PDF 145쪽)

이 장에서는 `Lifecycle` 인터페이스를 사용하는 방법을 배웠다. 이 인터페이스는 컴포넌트의 생명주기를 정의하고 다른 컴포넌트에 이벤트를 전달하는 우아한 방법을 제공한다. 또한 `Lifecycle` 인터페이스 덕분에 단 한 번의 시작/중지 작업으로 Catalina의 모든 컴포넌트를 시작하거나 중지할 수 있다.
