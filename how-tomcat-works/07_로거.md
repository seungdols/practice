# 7장: Logger(로거)

## 개요 (원본 PDF 145쪽)

로거(logger)는 메시지를 기록하는 컴포넌트다. Catalina에서 로거는 컨테이너에 연결되며, 다른 컴포넌트에 비해 상대적으로 단순하다. Tomcat은 `org.apache.catalina.logger` 패키지에 여러 종류의 로거를 제공한다. 이 장의 예제 애플리케이션은 `ex07.pyrmont` 패키지에 있다. 6장의 애플리케이션과 비교하면 `SimpleContext`와 `Bootstrap` 두 클래스가 변경되었다.

이 장은 세 부분으로 구성된다. 첫 번째 부분에서는 모든 로거가 구현해야 하는 `org.apache.catalina.Logger` 인터페이스를 다룬다. 두 번째 부분에서는 Tomcat의 로거들을 설명하고, 세 번째 부분에서는 Tomcat 로거를 사용하는 이 장의 예제 애플리케이션을 자세히 살펴본다.



## Logger 인터페이스 (원본 PDF 146쪽)

로거는 목록 7.1에 제시된 `org.apache.catalina.Logger` 인터페이스를 구현해야 한다.

**목록 7.1: Logger 인터페이스**

```java
package org.apache.catalina;
import java.beans.PropertyChangeListener;

public interface Logger {
  public static final int FATAL = Integer.MIN_VALUE;
  public static final int ERROR = 1;
  public static final int WARNING = 2;
  public static final int INFORMATION = 3;
  public static final int DEBUG = 4;

    public Container getContainer();
    public void setContainer(Container container);
    public String getInfo();
    public int getVerbosity();
    public void setVerbosity(int verbosity);
    public void addPropertyChangeListener(PropertyChangeListener
      listener);
    public void log(String message);

    public void log(Exception exception, String msg);
    public void log(String message, Throwable throwable);
    public void log(String message, int verbosity);
    public void log(String message, Throwable throwable, int verbosity);
    public void removePropertyChangeListener(PropertyChangeListener
      listener);
}
```

`Logger` 인터페이스는 구현 클래스가 선택해 호출할 수 있는 여러 `log` 메서드를 제공한다. 그중 가장 단순한 메서드는 기록할 메시지를 `String`으로 받는다.

마지막 두 `log` 메서드는 상세도(verbosity) 수준도 인자로 받는다. 전달한 값이 해당 인스턴스에 설정된 상세도 수준보다 낮으면 메시지를 기록하고, 그렇지 않으면 무시한다. 상세도 수준은 공개 정적 변수 다섯 개, 즉 `FATAL`, `ERROR`, `WARNING`, `INFORMATION`, `DEBUG`로 정의된다. `getVerbosity`와 `setVerbosity`는 이 값을 조회하고 설정하는 메서드다.

또한 `Logger` 인터페이스에는 로거 인스턴스를 컨테이너와 연결하는 `getContainer`, `setContainer` 메서드가 있다. `PropertyChangeListener`를 추가하거나 제거하는 `addPropertyChangeListener`, `removePropertyChangeListener`도 제공한다.

Tomcat의 로거 클래스에서 이 메서드들이 구현되는 방식을 살펴보면 더 명확해질 것이다.

## Tomcat의 로거 (원본 PDF 147쪽)

Tomcat은 `FileLogger`, `SystemErrLogger`, `SystemOutLogger`라는 세 종류의 로거를 제공한다. 이 클래스들은 `org.apache.catalina.logger` 패키지에 있으며 모두 `org.apache.catalina.logger.LoggerBase`를 상속한다. Tomcat 4에서 `LoggerBase`는 `org.apache.catalina.Logger` 인터페이스를 구현한다. Tomcat 5에서는 여기에 6장에서 설명한 `Lifecycle`과 20장에서 설명할 `MBeanRegistration`도 구현한다.

이 클래스들의 UML 다이어그램은 **그림 7.1: Tomcat의 로거**에 나와 있다(원본 PDF 147쪽 참조).

### LoggerBase 클래스

Tomcat 5의 `LoggerBase` 클래스는 MBean 생성 코드가 포함되어 상당히 복잡하다. MBean은 20장에서 다룰 것이므로 여기서는 Tomcat 4의 `LoggerBase`를 살펴본다. 20장의 설명까지 이해하면 Tomcat 5의 `LoggerBase`도 이해할 수 있을 것이다.

Tomcat 4에서 `LoggerBase`는 `log(String msg)`를 제외한 `Logger` 인터페이스의 모든 메서드를 구현하는 추상 클래스다.

```java
public abstract void log(String msg);
```

이 오버로드는 자식 클래스에서 실제 로깅을 수행하는 메서드다. 다른 모든 `log` 오버로드는 이 메서드를 호출한다. 자식 클래스마다 메시지를 기록하는 대상이 다르므로 `LoggerBase`에서는 이 메서드의 구현을 제공하지 않는다.

이 클래스의 상세도 수준을 살펴보자. 기본값은 `ERROR`이며, `verbosity`라는 `protected` 변수로 정의된다.

```java
protected int verbosity = ERROR;
```

`setVerbosity` 메서드를 호출하면서 `FATAL`, `ERROR`, `WARNING`, `INFORMATION`, `DEBUG` 중 하나의 문자열을 전달하면 상세도 수준을 변경할 수 있다. 목록 7.2는 `LoggerBase` 클래스의 `setVerbosity` 메서드를 보여준다.

**목록 7.2: setVerbosity 메서드**

```java
public void setVerbosityLevel(String verbosity) {
  if ("FATAL".equalsIgnoreCase(verbosity))
      this.verbosity = FATAL;
  else if ("ERROR".egualsIgnoreCase(verbosity))
      this.verbosity = ERROR;
  else if ("WARNING".equalsIgnoreCase(verbosity))
      this.verbosity = WARNING;
  else if ("INFORMATION".equalsIgnoreCase(verbosity))
      this.verbosity = INFORMATION;
  else if ("DEBUG".equalsIgnoreCase(verbosity))
      this.verbosity = DEBUG;
}
```

> 원문 코드에는 `egualsIgnoreCase`라고 표기되어 있다. 여기서는 원문을 그대로 보존했다.

두 `log` 메서드는 상세도 수준을 정수로 받는다. 이 오버로드에서는 전달된 상세도 수준이 인스턴스의 상세도 수준보다 낮을 때에만 `log(String message)` 오버로드를 호출한다. 목록 7.3은 이 두 오버로드를 보여준다.

**목록 7.3: 상세도 수준을 받는 log 메서드 오버로드**

```java
public void log(String message, int verbosity) {
  if (this.verbosity >= verbosity)
      log(message);
}
public void log(String message, Throwable throwable, int verbosity) {
  if (this.verbosity >= verbosity)
      log(message, throwable);
}
```

다음 절에서 설명할 `LoggerBase`의 세 자식 클래스에서는 `log(String message)` 오버로드의 구현을 확인할 수 있다.

### SystemOutLogger 클래스 (원본 PDF 148~149쪽)

이 `LoggerBase`의 자식 클래스는 `log(String message)` 오버로드를 구현한다. 받은 메시지는 모두 `System.out.println` 메서드로 전달한다. 목록 7.4에 `SystemOutLogger` 클래스가 나와 있다.

**목록 7.4: SystemOutLogger 클래스**

```java
package org.apache.catalina.logger;
public class SystemOutLogger extends LoggerBase {

    protected static final String info =
      "org.apache.catalina.logger.SystemOutLogger/1.0";

    public void log(String msg) {
      System.out.println(msg);
    }
}
```

### SystemErrLogger 클래스

이 클래스는 `SystemOutLogger`와 매우 비슷하지만 `log(String message)` 오버로드가 메시지 인자를 `System.err.println()` 메서드로 전달한다는 점이 다르다. 목록 7.5는 `SystemErrLogger` 클래스를 보여준다.

**목록 7.5: SystemErrLogger 클래스**

```java
package org.apache.catalina.logger;
public class SystemErrLogger extends LoggerBase {

    protected static final String info =
      "org.apache.catalina.logger.SystemErrLogger/1.0";
    public void log(String msg) {
        System.err.println(msg);
    }
}
```

### FileLogger 클래스 (원본 PDF 149~150쪽)

`FileLogger`는 `LoggerBase`의 자식 클래스 중 가장 정교하다. 연결된 컨테이너로부터 받은 메시지를 파일에 기록하며, 각 메시지에 선택적으로 타임스탬프를 붙일 수 있다. 이 클래스의 인스턴스를 처음 생성하면 오늘 날짜 정보가 이름에 포함된 파일을 만든다. 날짜가 바뀌면 새 날짜에 해당하는 파일을 생성하고 이후의 모든 메시지를 그 파일에 기록한다. 인스턴스에서는 로그 파일 이름의 접두사와 접미사도 지정할 수 있다.

Tomcat 4에서 `FileLogger`는 `Lifecycle` 인터페이스를 구현하므로 `org.apache.catalina.Lifecycle`을 구현하는 다른 컴포넌트와 마찬가지로 시작하고 중지할 수 있다. Tomcat 5에서는 `FileLogger`의 부모 클래스인 `LoggerBase`가 `Lifecycle`을 구현한다.

Tomcat 4의 `LoggerBase` 클래스에 있는 `start`와 `stop` 메서드(`Lifecycle` 인터페이스에서 상속받은 메서드)는 파일 로거의 시작과 중지에 관심이 있는 리스너에 생명주기 이벤트를 발생시키는 것 외에는 많은 일을 하지 않는다. 목록 7.6에 두 메서드가 나와 있다. `stop` 메서드는 로그 파일을 닫는 비공개 `close` 메서드도 호출한다. `close` 메서드는 이 절의 뒤에서 설명한다.

**목록 7.6: start 및 stop 메서드 (원본 PDF 150~151쪽에 걸쳐 있음)**

```java
public void start() throws LifecycleException {
  // Validate and update our current component state
  if (started)
      throw new LifecycleException
        (sm.getString("fileLogger.alreadyStarted"));
  lifecycle.fireLifecycleEvent(START_EVENT, null);
  started = true;
}

public void stop() throws LifecycleException {
  // Validate and update our current component state
  if (!started)
      throw new LifecycleException
       (sm.getString("fileLogger.notStarted"));
  lifecycle.fireLifecycleEvent(STOP__EVENT, null);
  started = false;
```

> 목록 7.6의 `stop()` 메서드는 다음 PDF 페이지에서 이어진다. `STOP__EVENT` 표기는 원문 그대로다.




### `stop()` 메서드의 마무리 (원본 PDF 151쪽)

앞 페이지에서 시작한 목록 7.6의 `stop()` 메서드는 다음 코드로 끝난다.

```java
    close ();
}
```

`FileLogger` 클래스에서 가장 중요한 메서드는 목록 7.7의 `log` 메서드다.

**목록 7.7: `log` 메서드**

```java
public void log(String msg) {
  // Construct the timestamp we will use, if reguested
  Timestamp ts = new Timestamp(System.currentTimeMillis());
  String tsString = ts.toString().substring(0, 19);
  String tsDate = tsString.substring(0, 10);

    // If the date has changed, switch log files
    if (!date.equals(tsDate)) {
        synchronized (this) {
          if (!date.equals(tsDate)) {
              close ();
              date = tsDate;
              open ();
          }
        }
    }

    // Log this message, timestamped if necessary
    if (writer != null) {
        if (timestamp) {
            writer.println(tsString + " " + msg);
        }
        else {
            writer.println(msg);
        }
    }
}
```

`log` 메서드는 메시지를 받아 로그 파일에 기록한다. `FileLogger` 인스턴스가 살아 있는 동안 `log` 메서드는 여러 로그 파일을 열고 닫을 수 있다. 일반적으로 날짜가 바뀌면 현재 파일을 닫고 새 파일을 여는 방식으로 로그 파일을 교체한다. `open`, `close`, `log` 메서드가 어떻게 동작하는지 살펴보자.

### `open` 메서드 (원본 PDF 152쪽)

목록 7.8의 `open` 메서드는 지정한 디렉터리에 새 로그 파일을 생성한다.

**목록 7.8: `open` 메서드**

```java
private void open() {
   // Create the directory if necessary
   File dir = new File(directory);
   if (!dir.isAbsolute())
       dir = new File(System.getProperty("catalina.base"), directory);
   dir.mkdirs();

    // Open the current log file
    try {
       String pathname = dir.getAbsolutePath() + File.separator +
          prefix + date + suffix;
       writer = new PrintWriter(new FileWriter(pathname, true), true);
    }
    catch (IOException e) {
       writer = null;
    }
}
```

먼저 로그 파일을 만들 디렉터리가 존재하는지 확인한다. 디렉터리가 없다면 새로 생성한다. 디렉터리 경로는 클래스 변수 `directory`에 저장되어 있다.

```java
File dir = new File(directory);
if (!dir.isAbsolute())
    dir = new File(System.getProperty("catalina.base"), directory);
dir.mkdirs();
```

그런 다음 디렉터리 경로, 접두사, 현재 날짜, 접미사를 조합해 열 파일의 경로명을 만든다.

```java
try {
    String pathname = dir.getAbsolutePath() + File.separator +
        prefix + date + suffix;
```

> 원문 PDF의 설명 중 해당 `try` 구문은 여는 중괄호가 아닌 여는 괄호로 인쇄되어 있다. 위에는 실제 목록 7.8의 표기를 사용했다.

이어서 `pathname` 경로에 데이터를 쓰는 `java.io.FileWriter`를 감싼 `java.io.PrintWriter` 인스턴스를 만든다. 이 `PrintWriter`는 클래스 변수 `writer`에 할당된다. `log` 메서드는 이 `writer`를 사용하여 메시지를 기록한다.

```java
writer = new PrintWriter(new FileWriter(pathname, true), true);
```

### `close` 메서드 (원본 PDF 153쪽)

`close` 메서드는 `PrintWriter`의 버퍼를 비우고, `PrintWriter`를 닫은 뒤, 해당 참조를 `null`로 설정하고 날짜를 빈 문자열로 바꾼다. 목록 7.9에 이 메서드가 나와 있다.

**목록 7.9: `close` 메서드**

```java
private void close() {
   if (writer == null)
       return;
   writer.flush();
   writer.close();
   writer = null;
   date = "";
}
```

### `log` 메서드 (원본 PDF 153~154쪽)

`log` 메서드는 `java.util.Date` 클래스를 얇게 감싼 `java.sql.Timestamp` 클래스의 인스턴스를 생성하는 것으로 시작한다. `Timestamp`를 사용하는 목적은 현재 날짜를 쉽게 얻기 위해서다. 현재 시간을 나타내는 `long` 값을 생성자에 전달한다.

```java
Timestamp ts = new Timestamp(System.currentTimeMillis());
```

`Timestamp` 클래스의 `toString` 메서드를 사용하면 현재 날짜를 문자열로 표현할 수 있다. 이 메서드의 출력 형식은 다음과 같다.

```text
yyyy-mm-dd hh:mm: SS.fffffffff
```

여기서 `fffffffff`는 00:00:00부터 경과한 나노초를 나타낸다. 날짜와 시각 부분만 얻기 위해 `log` 메서드는 `String` 클래스의 `substring` 메서드를 호출한다.

```java
String tsString = ts.toString().substring(0, 19);
```

그다음 `tsString`에서 날짜 부분만 얻기 위해 다음 코드를 사용한다.

```java
String tsDate = tsString.substring(0, 10);
```

이후 `log` 메서드는 `tsDate`를 문자열 변수 `date`의 값과 비교한다. `date`의 초기값은 빈 문자열이다. 두 값이 다르면 현재 로그 파일을 닫고, `date`에 `tsDate`를 할당한 뒤 새 로그 파일을 연다.

```java
// If the date has changed, switch log files
if (!date.equals(tsDate)) {
    synchronized (this) {
      if (!date.equals(tsDate)) {
          close();
          date = tsDate;
          open();
      }
    }
}
```

마지막으로 `log` 메서드는 로그 파일을 출력 대상으로 사용하는 `PrintWriter` 인스턴스에 메시지를 기록한다. 불리언 변수 `timestamp`가 `true`이면 메시지 앞에 타임스탬프(`tsString`)를 붙이고, 그렇지 않으면 접두사 없이 메시지만 기록한다.

```java
// Log this message, timestamped if necessary
if (writer != null) {
    if (timestamp) {
        writer.println(tsString + " " + msg);
    }
    else {
        writer.println(msg);
    }
}
```

## 애플리케이션 (원본 PDF 154~156쪽)

이번 장의 애플리케이션은 6장의 애플리케이션과 매우 비슷하지만 `SimpleContext` 객체에 연결된 `FileLogger`가 있다는 점이 다르다. 6장의 애플리케이션에서 바뀐 부분은 목록 7.10에 제시한 `ex07.pyrmont.startup.Bootstrap` 클래스의 `main` 메서드에서 확인할 수 있다. 특히 원문에서 강조 표시된 코드를 주의 깊게 살펴보자.

**목록 7.10: `Bootstrap` 클래스**

```java
package ex07.pyrmont.startup;

import ex07.pyrmont.core.SimpleContext;
import ex07.pyrmont.core.SimpleContextLifecycleListener;
import ex07.pyrmont.core.SimpleContextMapper;
import ex07.pyrmont.core.SimpleLoader;
import ex07.pyrmont.core.SimpleWrapper;
import org.apache.catalina.Connector;
import org.apache.catalina.Context;

import org.apache.catalina.Lifecycle;
import org.apache.catalina.LifecycleListener;
import org.apache.catalina.Loader;
import org.apache.calalina.loggor.FileLogger;
import org.apache.catalina.Mapper;
import org.apache.catalina.Wrapper;
import org.apache.catalina.connector.http.HttpConnector;

public final class Bootstrap {
  public static void main(String[] args) {
     Connector connector = new HttpConnector();
     Wrapper Wrapper1 = new SimpleWrapper();
     Wrapper1.setName("Primitive");
     Wrapper1.setServletClass("PrimitiveServlet");
     Wrapper wrapper2 = new SimpleWrapper();
     wrapper2.setName("Modern");
     Wrapper2.setServletClass("ModernServlet");
     Loader loader = new SimpleLoader();

    Context context = new SimpleContext();
    context.addChild(wrapper1);
    context.addChild(wrapper2);

    Mapper mapper = new SimpleContextMapper();
    mapper.setProtocol("http");
    LifecycleListener listener = new SimpleContextLifecycleListener();
    ((Lifecycle) context).addLifecycleListener(listener);
    context.addMapper(mapper);
    context.setLoader(loader);
    // context.addServletMapping(pattern, name);
    context.addServletMapping("/Primitive", "Primitive");
    context.addServletMapping("/Modern", "Modern");

     // ------ add logger --------
     System.setProperty("catalina.base",
System.getProperty("user.dir"));
     FileLogger logger = new FileLogger();
     logger.setPrefix("FileLog_");
     logger.setSuffix(".txt");
     logger.setTimestamp(true);
     logger.setDirectory("webroot");
     context.setLogger(logger);

        //--------------------------

        connector.setContainer(context);
        try {
           connector.initialize();
           ((Lifecycle) connector).start();
           ((Lifecycle) context).start();

            // make the application wait until we press a key.
            System.in.read();
            ((Lifecycle) context).stop();
        }
        catch (Exception e) {

            e.printStackTrace();
        }
    }
}
```

## 요약 (원본 PDF 156쪽)

이번 장에서는 로거 컴포넌트를 학습하고 `org.apache.catalina.Logger` 인터페이스를 살펴보았으며, 이 인터페이스를 구현한 Tomcat의 세 가지 구현체를 자세히 검토했다. 또한 이 장에 포함된 애플리케이션은 Tomcat에서 사용할 수 있는 가장 발전된 로거인 `FileLogger` 클래스를 사용한다.
