# 서문

## 개요

《How Tomcat Works》에 오신 것을 환영합니다. 이 책은 Tomcat 4.1.12와 5.0.18을 분석하고, 무료 오픈 소스 서블릿 컨테이너인 Catalina의 내부 동작을 설명합니다. Tomcat은 다양한 컴포넌트로 이루어진 복잡한 시스템입니다. Tomcat의 동작 방식을 배우려는 사람은 어디서부터 시작해야 할지 막막할 수 있습니다. 이 책은 먼저 전체 구조를 보여준 다음, 각 컴포넌트의 단순화된 버전을 직접 만들어 이해를 돕습니다. 실제 컴포넌트에 대한 설명은 그다음에 이어집니다.

먼저 이 서문을 읽으세요. 책의 구성과 직접 만들어 볼 애플리케이션의 개요를 소개합니다. ‘필요한 소프트웨어 준비하기’ 절에서는 다운로드할 소프트웨어와 코드 디렉터리 구조를 준비하는 방법을 안내합니다.

## 이 책의 대상 독자

이 책은 Java 기술을 다루는 모든 사람을 위한 것입니다.

- Servlet/JSP 프로그래머 또는 Tomcat 사용자로서 서블릿 컨테이너의 동작 원리를 알고 싶은 사람
- 기존 코드의 동작 방식을 이해하고 Tomcat 개발팀에 참여하려는 사람
- 웹 개발 경험은 없지만 소프트웨어 개발에 관심이 있고 Tomcat 같은 대규모 애플리케이션이 어떻게 설계되고 개발되었는지 배우고 싶은 사람
- Tomcat을 설정하거나 사용자 환경에 맞게 수정해야 하는 사람

이 책을 이해하려면 Java 객체 지향 프로그래밍과 서블릿 프로그래밍을 알아야 합니다. 서블릿이 익숙하지 않다면 관련 서적을 참고할 수 있습니다. 예를 들어 Budi의 《Java for the Web with Servlets, JSP, and EJB》가 있습니다. 이해를 돕기 위해 각 장은 해당 주제에 필요한 배경지식부터 설명합니다.

## 서블릿 컨테이너의 동작 방식

서블릿 컨테이너는 복잡한 시스템이지만, 서블릿 요청을 처리할 때 기본적으로 다음 세 가지 일을 수행합니다.

1. 호출할 서블릿이 사용할 파라미터, 헤더, 쿠키, 쿼리 문자열, URI 등의 정보를 담은 **요청 객체(request object)**를 생성합니다. 요청 객체는 `javax.servlet.ServletRequest` 또는 원문에 `javax.servlet.http.ServletRequest`라고 표기된 HTTP 요청 인터페이스의 인스턴스입니다.
2. 서블릿이 웹 클라이언트에 응답을 보낼 때 사용하는 **응답 객체(response object)**를 생성합니다. 응답 객체는 `javax.servlet.ServletResponse` 또는 원문에 `javax.servlet.http.ServletResponse`라고 표기된 HTTP 응답 인터페이스의 인스턴스입니다.
3. 요청 객체와 응답 객체를 인자로 전달해 서블릿의 `service` 메서드를 호출합니다. 서블릿은 요청 객체에서 값을 읽고 응답 객체에 결과를 씁니다.

> **원문 표기 주의:** `javax.servlet.http.ServletRequest`와 `javax.servlet.http.ServletResponse`는 원문에 인쇄된 명칭입니다. 실제 Servlet API의 HTTP 요청·응답 인터페이스는 `javax.servlet.http.HttpServletRequest`와 `javax.servlet.http.HttpServletResponse`입니다.

이후 각 장에서는 Catalina 서블릿 컨테이너를 자세히 살펴봅니다.

## Catalina 블록 다이어그램

Catalina는 정교하게 설계되고 개발된 소프트웨어이며 모듈화도 잘 되어 있습니다. 앞에서 설명한 서블릿 컨테이너의 역할을 기준으로 보면 Catalina는 크게 **Connector**와 **Container**라는 두 모듈로 나눌 수 있습니다.

*그림 I.1: Catalina의 주요 모듈 — Connector와 Container (그림은 원본 PDF 참조)*

그림 I.1은 물론 단순화된 모습입니다. 뒤의 장에서 더 작은 컴포넌트들을 하나씩 살펴봅니다.

Connector는 요청을 Container에 연결합니다. 수신한 HTTP 요청마다 요청 객체와 응답 객체를 만들고 처리를 Container에 넘깁니다. Container는 Connector에서 두 객체를 받아 서블릿의 `service` 메서드를 호출할 책임을 집니다.

다만 이것은 전체 동작의 극히 일부에 불과합니다. Container는 `service` 메서드를 호출하기 전에 서블릿을 로드하고, 필요하다면 사용자를 인증하며, 사용자의 세션을 갱신하는 등 많은 일을 수행합니다. 그래서 Container는 여러 모듈을 사용합니다. 예를 들어 **Manager**는 사용자 세션을 처리하고 **Loader**는 서블릿 클래스를 로드합니다.

## Tomcat 4와 5

이 책은 Tomcat 4와 5를 모두 다룹니다. 두 버전의 주요 차이점은 다음과 같습니다.

- Tomcat 5는 Servlet 2.4 및 JSP 2.0 명세를 지원하고, Tomcat 4는 Servlet 2.3 및 JSP 1.2를 지원합니다.
- Tomcat 5의 기본 Connector는 Tomcat 4의 기본 Connector보다 효율적입니다.
- Tomcat 5는 백그라운드 처리에 스레드를 공유하지만 Tomcat 4의 컴포넌트는 각자 백그라운드 처리 스레드를 갖습니다. 따라서 이 측면에서 Tomcat 5는 자원을 더 적게 사용합니다.
- Tomcat 5는 자식 컴포넌트를 찾기 위한 Mapper 컴포넌트가 필요하지 않아 코드가 단순해졌습니다.

## 각 장의 개요

이 책은 총 20장으로 구성됩니다. 처음 두 장은 입문 내용입니다. 1장에서는 HTTP 서버의 동작을, 2장에서는 간단한 서블릿 컨테이너를 설명합니다. 이어지는 두 장은 Connector를 다루며, 5장부터 20장까지는 Container 내부의 각 컴포넌트를 살펴봅니다.

> 참고: 각 장에는 설명 대상 컴포넌트와 유사한 기능을 구현한 예제 애플리케이션이 포함되어 있습니다.

**1장**에서는 간단한 HTTP 서버를 소개합니다. 동작하는 HTTP 서버를 만들려면 `java.net` 패키지의 `Socket`과 `ServerSocket` 클래스가 내부적으로 어떻게 작동하는지 알아야 합니다. 이 장에서는 예제 애플리케이션을 이해하는 데 충분한 배경지식을 제공합니다.

**2장**에서는 간단한 서블릿 컨테이너의 동작 방식을 설명합니다. 정적 리소스와 매우 단순한 서블릿 요청을 처리할 수 있는 서블릿 컨테이너 애플리케이션 두 개를 만들어 봅니다. 특히 요청 객체와 응답 객체를 만들고 요청 대상 서블릿의 `service` 메서드에 전달하는 방법을 배웁니다. 브라우저에서 호출할 수 있는 테스트용 서블릿도 포함되어 있습니다.

**3장**에서는 Tomcat 4 기본 Connector의 단순화된 버전을 소개합니다. 여기서 만드는 애플리케이션은 4장에서 다룰 Connector를 이해하기 위한 학습 도구입니다.

**4장**에서는 Tomcat 4의 기본 Connector를 설명합니다. 이 Connector는 더 빠른 Coyote Connector로 대체되어 더 이상 권장되지 않지만, 구조가 더 단순하고 이해하기 쉽습니다.

**5장**에서는 Container 모듈을 다룹니다. Container는 `org.apache.catalina.Container` 인터페이스로 표현되며 Engine, Host, Context, Wrapper의 네 종류가 있습니다. 이 장에서는 Context와 Wrapper를 사용하는 두 애플리케이션을 제공합니다.

**6장**에서는 `Lifecycle` 인터페이스를 설명합니다. 이 인터페이스는 Catalina 컴포넌트의 생명주기를 정의하고 컴포넌트에서 발생하는 이벤트를 다른 컴포넌트에 알리는 방법을 제공합니다. 또한 단 한 번의 시작/중지 동작으로 Catalina의 모든 컴포넌트를 시작하고 중지하는 메커니즘도 제공합니다.

**7장**에서는 오류 메시지와 기타 메시지를 기록하는 Logger 컴포넌트를 다룹니다.

**8장**에서는 Loader를 설명합니다. Loader는 웹 애플리케이션이 사용하는 서블릿 및 기타 클래스를 로드하는 중요한 Catalina 모듈입니다. 애플리케이션을 다시 로드하는 방법도 소개합니다.

**9장**에서는 세션 관리 컴포넌트인 Manager를 다룹니다. 다양한 Manager 유형과 세션 객체를 저장소에 영속화하는 방법을 설명합니다. 마지막에는 `StandardManager`를 사용해 세션 객체에 값을 저장하는 서블릿을 실행하는 애플리케이션을 만듭니다.

**10장**에서는 특정 콘텐츠에 대한 접근을 제한하는 웹 애플리케이션 보안 제약을 다룹니다. Principal, Role, 로그인 설정, Authenticator 등 보안 관련 개념을 배웁니다. `StandardContext` 객체에 인증용 Valve를 설치하고 기본 인증(Basic Authentication)을 사용하는 애플리케이션 두 개도 작성합니다.

**11장**에서는 웹 애플리케이션의 서블릿을 표현하는 `org.apache.catalina.core.StandardWrapper` 클래스를 자세히 설명합니다. 특히 Filter와 서블릿의 `service` 메서드가 호출되는 과정을 다룹니다. 예제 애플리케이션은 `StandardWrapper` 인스턴스로 서블릿을 표현합니다.

**12장**에서는 웹 애플리케이션을 표현하는 `org.apache.catalina.core.StandardContext` 클래스를 다룹니다. `StandardContext` 객체의 설정 방법, HTTP 요청을 받을 때 내부에서 일어나는 일, 자동 재로딩 지원 방식, Tomcat 5가 관련 컴포넌트의 주기적 작업을 실행하는 스레드를 공유하는 방식을 설명합니다.

**13장**에서는 나머지 두 Container인 Host와 Engine을 소개하고 표준 구현인 `org.apache.catalina.core.StandardHost`와 `org.apache.catalina.core.StandardEngine`을 살펴봅니다.

**14장**에서는 Server와 Service 컴포넌트를 설명합니다. Server는 전체 서블릿 컨테이너를 시작하고 중지하는 메커니즘을 제공하고, Service는 하나의 Container와 하나 이상의 Connector를 보유합니다. 예제에서는 Server와 Service를 사용하는 방법을 보여줍니다.

**15장**에서는 Apache Software Foundation의 오픈 소스 프로젝트인 Digester를 사용한 웹 애플리케이션 설정을 설명합니다. Digester 라이브러리의 기본 사용법과 XML 문서의 노드를 Java 객체로 변환하는 방법을 먼저 소개한 다음, `StandardContext` 인스턴스를 설정하는 `ContextConfig` 객체를 설명합니다.

**16장**에서는 사용자가 정상적인 종료 명령을 보내든 콘솔을 그냥 닫든 Tomcat이 정리 작업을 수행할 기회를 확보하기 위해 사용하는 Shutdown Hook을 설명합니다.

**17장**에서는 배치 파일과 셸 스크립트를 이용해 Tomcat을 시작하고 중지하는 방법을 다룹니다.

**18장**에서는 웹 애플리케이션의 배포 및 설치를 담당하는 Deployer 컴포넌트를 소개합니다.

**19장**에서는 서블릿이 Catalina 내부 객체에 접근하도록 해 주는 특수 인터페이스 `ContainerServlet`을 설명합니다. 특히 배포된 애플리케이션을 관리하는 Manager 애플리케이션을 다룹니다.

**20장**에서는 JMX를 설명하고, Tomcat이 내부 객체에 대한 MBean을 만들어 관리 가능하게 하는 방법을 다룹니다.

## 각 장의 애플리케이션

각 장에는 Catalina의 특정 컴포넌트에 초점을 맞춘 하나 이상의 애플리케이션이 포함됩니다. 보통 해당 컴포넌트의 단순화된 구현이거나 Catalina 컴포넌트의 사용법을 보여 주는 코드입니다. 예제의 모든 클래스와 인터페이스는 `ex[장 번호].pyrmont` 패키지 또는 그 하위 패키지에 속합니다. 예를 들어 1장의 애플리케이션 클래스는 `ex01.pyrmont` 패키지에 있습니다.

## 필요한 소프트웨어 준비하기

이 책의 예제 애플리케이션은 J2SE 1.4에서 실행됩니다. 압축된 소스 파일은 저자 웹사이트에서 다운로드할 수 있으며, Tomcat 4.1.12의 소스 코드와 책에서 사용하는 애플리케이션 코드가 들어 있습니다.

J2SE 1.4가 설치되어 있고 `PATH` 환경 변수에 JDK 경로가 포함되어 있다고 가정하고 다음 단계를 진행하세요.

1. ZIP 파일의 압축을 풉니다. 압축 해제된 파일은 `HowTomcatWorks`라는 새 디렉터리에 들어갑니다. 이 디렉터리가 작업 디렉터리입니다. 그 아래에는 필요한 라이브러리를 담은 `lib`, 소스 파일을 담은 `src`, HTML 파일과 세 개의 예제 서블릿을 담은 `webroot`, 예제 애플리케이션을 담은 `webapps` 등의 하위 디렉터리가 있습니다.
2. 작업 디렉터리로 이동해 Java 파일을 컴파일합니다. Windows에서는 `win-compile.bat`를 실행합니다. Linux에서는 필요한 경우 실행 권한을 부여한 뒤 다음 명령을 실행합니다.

```bash
./linux-compile.sh
```
